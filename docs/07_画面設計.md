# 07 画面設計

SESN (System Engineer Sales Navigator)

## 1. 目的

SES営業の情報量と操作頻度に耐えながら、状況把握と次の行動を迷わず行える画面構成を定義する。機能要件を維持しつつ、モダンで信頼感があり、長時間利用しても疲れにくいUIを採用する。

## 2. デザイン原則

- 営業PCを最優先し、タブレットとスマートフォンへ段階的に対応
- 左サイドバー＋上部ヘッダー＋メイン領域＋補助パネル
- 状態、期限、金額、要対応を最初に把握できる構成
- 主要操作は右上または固定操作バーに集約
- 危険操作は通常操作から分離
- AIは必要時だけ右サイドパネルに表示
- 色だけで状態を表現しない
- 一覧を高密度にしすぎず、主情報と補足を2段表示
- 詳細画面では「現在の状態」と「次に必要な操作」を優先

## 4. 共通一覧レイアウト

1. ページタイトルと新規登録
2. KPI・クイックフィルター
3. クイック検索
4. フィルター、保存検索、表示項目、エクスポート
5. 一覧
6. ページングまたはカーソル読み込み
7. 選択時のみ一括操作バー

一覧行は主情報と補足情報を2段で表示する。期限は日付と残日数、状態はラベルとアイコンを併記する。行クリックで右側クイック詳細を開き、軽微な操作は画面遷移なしで行える。

3. 主要アクション
4. 状況サマリーカード
5. タブ
6. メイン情報
7. 右側アクションセンター

アクションセンターには次の対応、期限、未完了、承認状況、アラート、AIインサイトを表示する。

## 8. 技術者管理

### 一覧

検索条件:

- 氏名・管理番号
- 所属会社
- スキル
- 経験年数
- 稼働状況
- 稼働可能日
- 希望単価
- 最寄駅
- 契約形態
- 担当営業
- タグ

主表示:

- 表示名
- 主要スキル
- 経験年数
- 稼働状態
- 希望単価
- 最寄駅
- 提案・面談件数
- AIマッチスコア

### 詳細タブ

- 基本情報
- スキル
- 職務経歴
- 希望条件
- 提案・面談履歴
- 添付
- コメント
- 監査履歴

### 登録・編集

基本情報、所属・契約、スキル、希望条件、職務経歴、添付、確認のステップ形式。氏名、連絡先、生年月日、所属、経歴書特徴量による重複候補を表示し、別人登録時は理由を必須とする。

### 経歴書

アップロード、ウイルスチェック、AI解析、レビュー、正式反映の順とする。旧版を保持し、提案時の利用版を固定する。

### 比較・マッチング

最大5名程度を比較し、一致点、注意点、単価、稼働日、勤務地、実績、AI根拠を表示する。AIスコアだけで自動提案しない。

## 9. 顧客管理

### 一覧

顧客区分、業種、地域、取引状態、担当、最終接触日、契約更新、要フォロー等で検索する。

### 詳細タブ

- 基本情報
- 担当者
- 案件
- 提案
- 契約・参画
- 営業活動
- 添付
- コメント
- 監査履歴

顧客360度ビューとして、関係性、売上・粗利、案件パイプライン、更新予定、最近の接点、未完了タスク、AI注意点を上部にまとめる。

担当者は決裁者、予算責任者、実務担当等の関係性と連絡可否を管理する。信用・リスク情報は通常メモから分離し、項目権限と閲覧監査を適用する。

## 10. 案件管理

### 一覧

状態、顧客、職種、スキル、単価、勤務地、リモート、開始日、商流、契約形態、提案状況、担当、タグで検索する。

### 詳細タブ

- 基本情報
- 要件
- 契約・単価条件
- 勤務条件
- 提案
- 面談
- 契約・参画
- 営業活動
- 添付
- コメント
- 監査履歴

要件変更時は変更前後と理由を表示し、既存提案、再承認、再送信への影響を通知する。

### マッチング・進捗

候補者比較、AIマッチング、提案進捗カンバン、提案不足アラートを提供する。カンバン移動は状態遷移ルールに従い、理由・承認が必要な遷移は専用ダイアログを表示する。

## 11. 提案管理

### 一覧

下書き、承認待ち、差戻し、送信待ち、送信済み、送信失敗、取消、訂正中をクイックフィルターで表示する。

### 詳細タブ

- 提案内容
- 技術者情報
- 提案資料
- 承認
- 送信
- 顧客反応
- 面談・成約
- コメント
- 監査履歴

### 作成

案件・技術者選択、条件確認、提案内容、添付、送信内容、承認確認、最終確認のステップ形式。

提案前にスキル、単価、開始日、契約形態、商流、経歴書版、個人情報公開範囲を検証する。重大な不一致は送信不可、軽微な警告は理由入力で継続可能とする。

承認後編集は再承認必須。送信済みの誤りは訂正フローを使用し、再提案は元提案を開き直さず新規作成する。

## 12. 面談管理

### 一覧

本日、今週、結果未入力、次回調整中、見送り、成約候補を表示する。

### 詳細タブ

- 基本情報
- 対象情報
- 面談準備
- 参加者
- 結果
- 連絡履歴
- 添付
- コメント
- 監査履歴

### 日程調整

複数候補日時と顧客・技術者の回答を表示し、双方可となった候補を営業が確定する。カレンダー、Meet、Teams、Zoom等との連携状態を表示する。

面談結果は顧客評価と社内評価を分離し、見送り理由はコードと自由記述を保持する。次回面談は前回を上書きせず、新規レコードとして作成する。

## 13. 契約管理

### 一覧

下書き、確認待ち、承認待ち、相手方確認、締結待ち、契約中、更新確認、終了予定、事前取消、中途解約を表示する。

### 詳細タブ

- 基本情報
- 契約条件
- 契約期間・更新
- 締結情報
- 参画情報
- 変更履歴
- 添付
- コメント
- 監査履歴

契約登録は成約情報から下書きを生成し、人が確認して確定する。提案との差分、粗利、支払サイト、商流、再委託、必要書類を事前チェックする。

更新時は旧契約を上書きせず、新契約を作成し`previousContractId`を保持する。単価変更は適用日と変更前後を表示する。開始前取消、中途解約、訂正は専用画面と理由・監査を必須とする。

## 14. 参画管理

### 一覧

参画中、開始前、更新確認中、終了予定、期限30日以内、問題あり、長期未フォローを表示する。

### 詳細

上部に参画状態、契約残日数、月額粗利、次回確認、稼働場所、出社頻度、担当、健康状態を表示する。

タブ:

- 概要
- 契約・条件
- 稼働状況
- 活動履歴
- 評価・フォロー
- 問題・インシデント
- 添付
- コメント
- 監査履歴

開始前チェックリスト、月次フォロー、条件変更、更新確認、終了チェックリストを提供する。重大準備項目が未完了の場合は開始済みに変更できない。

問題・インシデントは通常コメントと分離し、重要度、対応状態、公開範囲を管理する。

## 15. AI機能

AIは全画面共通の右サイドパネルと専用実行・レビュー画面を提供する。

### サイドパネル

- 自然言語検索
- 要約
- マッチング
- 提案文・メール文生成
- リスク確認
- 類似データ検索
- 操作ガイド

現在の画面コンテキスト、対象データ、利用目的を実行前に表示する。

### 実行・レビュー

長時間処理は非同期ジョブとして進捗を表示する。レビュー画面ではAIスコア、一致、不一致、注意点、使用データ、対象期間、モデル、プロンプト版、信頼度を表示し、人が承認・却下・保留する。

### 管理

- AI実行履歴
- プロンプト版管理
- モデル設定
- 利用状況・コスト
- 成功率・採用率
- 利用上限・異常アラート

AI結果は自動送信、自動承認、自動更新しない。

## 16. 管理画面

一般業務画面と管理者モードを視覚的に区別し、左側に管理メニューを配置する。

対象:

- ユーザー
- 組織
- ロール・権限
- 承認ルール
- APIキー
- Webhook
- ジョブ
- AI設定
- 監査ログ
- マスタ

設定変更時は変更前後、影響範囲、理由、反映タイミングを表示する。危険操作は二段階確認を行う。

## 17. 通知・タスク

通知は出来事、タスクは実作業として分離する。

通知分類:

- 要対応
- 承認
- 期限
- 面談
- 契約
- AI
- システム
- エラー

タスク状態:

- 未着手
- 対応中
- 保留
- 完了
- 取消
- 期限超過

業務状態から承認、結果入力、更新確認等のタスクを自動生成できる。

## 18. グローバル検索・コマンドパレット

顧客、担当者、案件、技術者、提案、面談、契約、参画、コメント、ファイル名を横断検索する。権限のないデータは存在自体を表示しない。

`Ctrl / Command + K`で画面移動、管理番号検索、新規作成、承認待ち表示、AI実行を呼び出せる。

## 19. コメント・ファイル

コメントはメンション、添付、公開範囲、解決状態、編集版履歴を持つ。

ファイルはアップロード中、スキャン中、利用可能、解析中、解析済み、隔離、削除済み、期限切れを表示する。提案利用中の版は差し替え後も固定する。

## 20. バリデーション・エラー

入力項目直下と画面上部の両方にエラーを表示する。

区分:

- エラー: 処理不可
- 警告: 理由入力で継続可能
- 確認: 内容確認が必要
- 情報: 参考情報

競合時は自分の変更と最新値の差分を表示する。システムエラー時はrequestIdと再試行、サポート情報コピーを提供する。

## 21. 非同期処理

短時間処理はスケルトン・ボタン内進捗を使用し、長時間処理はジョブとしてバックグラウンド実行する。画面を閉じても継続し、完了通知、一部成功内訳、エラーファイルを提供する。

## 22. 空状態

データなし、検索結果なし、権限なしを区別する。空白だけを表示せず、次に可能な操作を示す。検索結果0件では解除効果が高い条件を提案する。

## 23. アクセシビリティ

WCAG 2.2 AA相当を目標とする。

- キーボード操作
- 明確なフォーカス
- 色以外の状態表現
- 十分なコントラスト
- ラベルと入力の関連付け
- 読み上げ可能なエラー
- 表見出し
- アイコン説明
- 動きを減らす設定
- 200%拡大対応

## 24. レスポンシブ

PCでは左ナビ、一覧テーブル、右パネル、複数列を使用する。タブレットではナビを折りたたみ、詳細を1列化する。スマートフォンは通知、承認、予定、簡易結果入力、コメント、タスク、基本情報確認を中心とし、大量編集や契約書確認はPCを推奨する。

## 25. デザインシステム

共通コンポーネント:

- Button / Icon Button
- Input / Select / Date Picker
- Checkbox / Radio / Switch
- Chip / Status Badge
- Card / Table / Tabs
- Modal / Drawer
- Toast / Alert / Tooltip
- Skeleton / Stepper / Timeline
- Empty State

8pxを基本単位とし、8・16・24・32pxで余白を統一する。背景は淡いグレー、情報領域は白、選択は薄い青、AI関連は紫系アクセントを使用する。角丸と影は控えめにし、信頼感を優先する。

## 26. パフォーマンス

- 初期表示は主要情報を優先
- 詳細タブは遅延読み込み
- 一覧は必要項目のみ取得
- 大量一覧は仮想スクロールを検討
- PDF・画像は遅延読み込み
- AI結果は段階表示

## 27. プロトタイプ方針

本設計を基に、主要画面をHTMLプロトタイプで作成する。対象はダッシュボード、案件一覧・詳細、技術者一覧・詳細、提案作成・承認、契約詳細、参画詳細、管理画面とする。画像生成ではなくHTMLを優先し、迅速に操作感を確認できるようにする。
