# 02_要件定義

SESN (System Engineer Sales Navigator)

> 本書はヒアリングで確定した要件を随時反映するリビングドキュメントとする。GitHub上の本ファイルを正本（Single Source of Truth）として扱う。

---

## 1. 基本方針

- AIは営業判断を支援するが、最終判断は営業担当者が行う。
- AIが作成・更新した候補は、営業担当者の確認・承認後に反映する。
- 主要な業務履歴は分析と監査に利用できるよう保存する。
- 詳細な評価尺度は、技術者・案件・BPなどを横断してDB設計直前に統一設計する。

---

## 2. 技術者管理（今回までの確定事項）

### 2.1 連絡先

以下を管理する。

- メールアドレス
- 電話番号

### 2.2 希望条件

以下を時系列で履歴管理する。

- 希望単価
- 希望勤務地
- リモート可否
- その他希望条件

### 2.3 資格

以下を管理する。

- 資格名
- 取得日
- 有効期限
- 資格番号

### 2.4 稼働予定

以下を管理する。

- 稼働開始日
- 稼働終了予定日
- 提案可能日

### 2.5 評価

営業担当者による総合評価を管理する。評価尺度と入力方式はDB設計直前に統一設計する。

---

## 3. BP管理

### 3.1 管理単位

- BP会社とBP担当者を分けて管理する。
- BP技術者はBP会社に紐付ける。
- 提案先はBP担当者単位で管理する。
- 担当者は物理削除せず、異動・退職などをステータスで管理する。

### 3.2 BP会社評価

BP会社の総合評価を管理する。評価尺度はDB設計直前に統一設計する。

### 3.3 BP担当者評価

担当者ごとの評価を管理する。評価観点の例は以下とする。

- 対応速度
- レスポンス品質
- 提案品質
- 信頼度

評価尺度はDB設計直前に統一設計する。

### 3.4 契約状況

BP会社の契約状況を管理する。

初期ステータス：

- 契約前
- 契約中
- 契約注意
- 休止
- 契約終了

その他のステータスは運用設計時に追加検討する。

### 3.5 契約注意の扱い

- 契約注意のBP会社も案件紹介・技術者提案の対象とする。
- 画面上で「注意」を目立つように表示する。
- 営業担当者の判断で検索結果・提案候補から除外できるようにする。
- AIは契約注意のみを理由に自動的な完全除外を行わない。
- 最終的な提案可否は営業担当者が判断する。

契約注意に関して、以下を管理可能な設計とする。

- 注意理由
- 注意開始日
- 解除日
- 注意メモ

契約状況と注意状態は将来的に分離できる設計を優先し、「契約中だが注意あり」の状態も表現できるようにする。

### 3.6 得意分野

BP会社ごとに得意分野を管理する。

例：

- Java
- C#
- インフラ
- SAP
- AI
- 金融
- 公共

将来的にスキルマスタおよび業界マスタとの連携を検討する。

### 3.7 取引実績

提案履歴・案件履歴から以下を自動集計し、BP会社画面に表示する。

- 提案件数
- 成約件数
- 成約率
- 最終提案日
- 最終成約日
- 最終取引日

## 4. 提案管理

### 4.1 提案先

技術者の提案先はBP担当者単位で管理する。

### 4.2 提案ステータス

設計上は詳細なステータスを保持し、画面では運用に応じて簡略表示できるようにする。

初期ステータス候補：

- 提案中
- 書類選考中
- 面談調整中
- 面談予定
- 面談済
- 面談結果待ち
- 成約
- 見送り
- 辞退

追加候補：

- 再提案予定
- 保留
- 条件交渉中

ステータスはマスタ管理を基本とし、変更履歴を保存する。

### 4.3 提案時の経歴書

- 提案時に使用した経歴書の版を保存する。
- 現在の最新版とは別に、提案時点の証跡を保持する。
- 提案後に経歴書が更新された場合、再送信または面談時に最新版を使用できるようにする。

提案履歴で管理する項目候補：

- 提案時経歴書ID
- 現在の最新経歴書ID
- 最新版との差分有無
- 再送要否
- 再送済みフラグ
- 再送日時
- 面談時最新版持参予定フラグ

### 4.4 提案メール

以下の各段階の文面を保存する。

- AIが生成した提案文
- 営業担当者が編集した文面
- 実際に送信した本文

必要に応じて生成日時、編集者、送信日時、送信先を保持する。

### 4.5 見送り・辞退理由

見送り・辞退理由を管理する。

初期理由候補：

- スキル不足
- 単価不一致
- 稼働時期不一致
- 面談NG
- 顧客都合
- 本人辞退
- 他社決定
- 要員充足

理由はマスタ選択と自由記述を組み合わせ、複数理由を登録可能な設計を検討する。

### 4.6 分析・AI活用

以下を将来のAIマッチング改善と営業分析に利用できるよう蓄積する。

- 提案結果
- 成約理由
- 見送り理由
- 辞退理由
- 提案から各ステータスまでの所要時間
- BP会社・担当者別の成約率
