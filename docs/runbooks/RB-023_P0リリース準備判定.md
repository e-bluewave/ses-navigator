# RB-023 P0リリース準備判定

## 目的

P0バックログの「GitHub上の実装完了」と「Productionへ昇格できる状態」を分離し、未完了の実環境検証・業務承認・製品選定が残っている状態でProduction Readyと誤判定しない。

## 判定原則

- P0はBA-001〜BA-020の20件を対象とする。
- `verified` は実環境検証または正式な業務確認まで完了した項目だけに使用する。
- `pending` は実装済みでも実環境検証、訓練、業務承認等が残る項目に使用する。
- `deferred` は本番要件の確定や製品選定等が未完了で、現時点で完了扱いできない項目に使用する。
- `pending` と `deferred` はどちらもProduction Readyを満たさない。
- 20件すべてが`verified`になった場合のみProduction Readyとする。

## 現在のverified項目

- BA-001: Staging/ProductionのSupabase・Vercel分離、環境別Secret分離、実環境binding確認、Staging Auth/主要API/Data API smoke、Production read-only health smoke、Migration parity、外部証跡validator完了
- BA-002: Staging/Productionのregion整合、Vercel FunctionsのTokyo固定、Data API runtime binding、Staging認証済み案件API 100回Latency実測（100/100成功・Error 0%）、Production healthのTokyo実行確認完了
- BA-004: Data API統合実環境セキュリティ検証とcleanup完了
- BA-018: Data API権限面の統合実環境回帰確認完了
- BA-019: Migration 159実環境適用後のBA-019 postcheck完了（`BA019_POSTCHECK_PASSED`、`raw_sensitive_surface=closed`、`project_source_summary=verified`）
- BA-020: Exposed schemas設定と統合実環境確認完了

その他の項目は、GitHub上のRunbook・policy・CI実装が完了していても、必要な実環境検証や業務判断が残るため`verified`にはしない。

## 自動判定

通常確認:

```bash
pnpm release:readiness
```

このコマンドはポリシー構造を検査し、現在の`productionReady`、`verified`、`pending`、`deferred`を出力する。Production Readyでないこと自体は通常CI失敗にしない。

Production昇格ゲート:

```bash
pnpm release:readiness:require
```

P0が1件でも`pending`または`deferred`の場合は失敗し、Productionリリースを停止する。

単体テスト:

```bash
pnpm release:readiness:check
```

## 更新ルール

1. P0項目の状態変更は、対応する証跡を確認してから行う。
2. Secret、DB URL、Project Ref、個人情報、復旧済み実データ等を証跡文字列へ記録しない。
3. `verified`への変更は、RunbookやCIの存在だけでは認めない。
4. 実環境検証が必要な項目は、Staging等の適切な非Production環境で確認する。
5. BA-001は実Project分離、実環境binding、Stagingの主要smoke、Productionの読み取りsmoke、外部証跡validatorがPASSするまで`pending`を維持し、PASS確認後は`verified`へ更新する。
6. BA-002はStaging/Productionのregion整合、runtime binding、Staging主要APIのLatency実測、Production Function region確認が完了するまで`pending`を維持し、PASS確認後は`verified`へ更新する。
7. BA-019はMigration 159の実環境適用とBA-019 postcheckがPASSするまで`pending`を維持し、PASS確認後は`verified`へ更新する。
8. BA-012、BA-014は要件が未確定の間`deferred`を維持し、Production Readyにはしない。

## Production判定

`pnpm release:readiness:require`が成功し、通常CI、必要なStaging検証、業務責任者の承認がすべて揃った場合のみProduction昇格候補とする。
