# RB-017 ファイルマルウェア検査

## 目的

SES Navigatorで扱う経歴書・契約・請求関連ファイル等について、ファイル本体を外部SaaSへ送信せず、管理下の環境でマルウェア検査・隔離・再検査・誤検知対応を行う。

## 現時点の確定事項

- ファイル本体を外部ウイルス検査SaaSへ送信しない。
- 検査エンジンの製品選定は保留し、後から差し替え可能な構成とする。
- 未検査・検査失敗・判定不能ファイルは利用可能状態へ昇格させない。
- スキャン処理はfail closedとする。

## 状態遷移

1. upload accepted
2. quarantined
3. scanning
4. clean -> released
5. infected -> quarantined/blocked
6. error or unknown -> quarantined/retry

`clean`以外はアプリ利用・通常ダウンロード対象にしない。

## スキャナ要件

- 自社または契約上の専用管理環境内で動作すること。
- ファイル本体を第三者SaaSへ転送しないこと。
- エンジンや署名データを更新できること。
- health checkを持つこと。
- timeout/engine failure時はclean扱いにしないこと。
- scan結果として、検査時刻、engine version、definition/signature version、判定、再検査回数、request/run ID相当を記録できること。

## 隔離

隔離中ファイルは通常公開領域と論理的に分離する。署名URL等による迂回利用を禁止し、アプリは`clean`状態のみ参照可能とする。

## 再検査

以下の場合は再検査する。

- engine/definition更新後
- error/unknown
- 運用担当が再検査を指示した場合
- false positive調査後

感染判定されたファイルを自動releaseしてはならない。

## 誤検知対応

誤検知の可能性がある場合も自動解除しない。担当者レビュー、再検査、根拠記録を行い、手動releaseには承認を必須とする。

## 証跡

GitHubや一般ログへファイル本体、個人情報、秘密情報、Production識別子を保存しない。残す証跡はrequest/run ID、結果、時刻、engine/definition version、再検査結果、承認記録などメタデータに限定する。

## エンジン選定

BA-012の第1段階では製品を固定しない。候補はローカル/self-hostedで完結できるものに限定する。選定時は以下を確認する。

- 外部ファイル送信が不要
- 更新方式
- ライセンス/費用
- Windows/Linux運用性
- 最大ファイルサイズ/timeout
- アーカイブ・Office・PDF等の対応
- 検知性能とfalse positive運用
- コンテナ/ワーカー化の容易さ

製品選定は別途意思決定事項とする。

## BA-012完了条件

1. 実際の検査エンジンを選定する。
2. Stagingでquarantine -> scan -> release/blockを確認する。
3. error/timeout時のfail closedを確認する。
4. definition更新後の再検査を確認する。
5. false positive手動releaseを確認する。
6. ファイル本体が外部検査SaaSへ送信されないことを確認する。
