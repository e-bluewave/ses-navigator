# RB-019 負荷試験

## 目的

本番開始前に、匿名化または合成した本番相当データを用いて、RLS・一覧・検索・Bulk処理・締め処理相当の性能と安定性を確認する。

## 安全条件

- Production環境へ負荷試験を実施しない。
- Productionの個人情報・経歴書本文・契約本文等を試験データへコピーしない。
- Production Secretを使用しない。
- Stagingまたは専用の破棄可能な負荷試験環境を使用する。
- テナント境界・RLSを有効にした実運用相当経路で測定する。

## 必須シナリオ

- 案件一覧
- 案件検索
- 技術者一覧
- 技術者検索
- 会社一覧
- 複数テナント並行アクセス時のRLS境界
- Bulk write
- 月末・締め処理相当の集計または財務処理

## 必須計測

各シナリオで以下を記録する。

- request count / throughput
- p50 / p95 / p99 latency
- error rate
- DB connection usage
- slow SQL
- lock wait / long transaction
- CPU・memory・database capacity（取得可能な範囲）
- job backlog / oldest job age（該当時）

BA-013の監視項目と同じ観測面を用い、負荷試験結果をBA-013のalert threshold調整へ返す。

## 試験段階

1. smoke: 1ユーザー相当でシナリオ成立を確認
2. baseline: 想定通常負荷で計測
3. peak: 想定ピーク負荷で計測
4. stress: 合否対象外の上限探索として段階的に負荷を増加
5. recovery: 負荷低下後に接続・job・latencyが正常へ戻ることを確認

## 未確定事項

以下は業務規模・本番利用想定に依存するため、プロジェクト責任者の決定後に固定する。

- 同時利用者数
- 1テナント当たり案件件数
- 1テナント当たり技術者件数
- 1テナント当たり会社件数
- 1テナント当たり応募・提案件数
- 合否とする応答時間・error rateの最終目標

これらを推測でProduction基準にしてはならない。

## BA-014完了条件

1. 本番想定の負荷規模を承認する。
2. 匿名化・合成データセットを作成する。
3. baseline / peak試験をStagingまたは専用環境で実施する。
4. RLS境界違反が0件であることを確認する。
5. 合否基準内のlatency/error rateであることを確認する。
6. DB connection・slow SQL・lock・job backlogを記録する。
7. BA-013監視しきい値を実測結果で再調整する。
8. ボトルネックと改善内容を記録する。
