# エンジニア案件・仕事探しサイト調査

- 調査日: 2026-09-27
- 対象: 日本国内のITエンジニア向け求人・案件・スカウト・副業・SES関連Webサービス
- 目的: SES Navigatorの案件収集・技術者獲得・外部データ連携戦略の判断材料とする
- 注意: 案件数は各サイトの検索条件・更新時点・「掲載累計/現在募集中」の定義により変動する。数値は固定値としてDB設計に利用しない。
- 注意: API/RSS/スクレイピング欄は「技術的に取得できるか」ではなく、公式に利用可能と確認できるかを重視する。未確認のものは「未確認」とする。

## 1. 調査結果の要約

ITエンジニアの仕事探しは単一サイトではなく、転職サイト、転職エージェント、スカウト型、エンジニア特化型、フリーランス案件サイト、案件横断検索、リファラル/SNS等を併用する構造になっている。

SES Navigatorにとって特に重要なのは以下の2種類のデータを分けて考えることである。

1. **案件データ**: 案件名、業務内容、必須/歓迎スキル、単価、勤務地、リモート、開始日、期間、商流、契約形態等
2. **技術者データ**: スキル、経験年数、希望条件、稼働状況、勤務地、リモート希望等

将来的には「外部案件情報 → 正規化 → 重複排除 → 技術者DBとのAIマッチング」へ発展させる。

## 4. 調査から得られた開発上の示唆

- エンジニアは単一サイトではなく複数チャネルを併用する。
- 「求人/案件データ」と「技術者プロフィールデータ」は別のデータ群として扱う。
- スカウト型サービスでは、技術実績・スキル情報そのものが重要なデータになる。
- 案件サイトの「掲載件数」と「現在募集中件数」は一致しない。
- 外部サイトのHTMLを直接DBへ保存するのではなく、SES Navigator内部の共通スキーマへ正規化する。
- 外部データは source_site / source_job_id / source_url / first_seen_at / last_seen_at / status を持たせ、重複と終了案件を管理できるようにする。
- 無許可スクレイピングを前提にした機能は作らない。
- MVP1では外部サイト自動収集を必須機能にしない。
- MVP2以降で「案件URLを登録 → AIで構造化」を優先的に検討する。
- APIや正式なデータ提供契約が利用できるサイトは、その後に自動連携を検討する。

## 6. 更新ルール

この文書の案件数・サービス仕様は変動するため、固定的な事実として扱わない。

外部連携を実装する際は、必ずその時点の以下を再確認する。

1. 公式APIの有無
2. API利用条件
3. データ再利用・保存条件
4. 利用規約
5. robots.txt
6. 個人情報・プロフィール情報の取扱い
7. 案件情報の著作権/再利用条件
8. レート制限
9. 認証方式
10. サービス終了・仕様変更

調査資料の更新と実装判断を分離し、実装前に最新条件を確認する。
